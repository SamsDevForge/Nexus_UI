# NEXUS workspace UI review — 21 November 2026

Owner-requested UI iteration after merging PR #5 (`dd576dbe`), under D-040.
This is a visual/usability refinement, not Phase 11 integration or deployed
acceptance. The landing/cube modules and service boundaries are preserved.

## Evidence and scope

Compared the same routes at 1440×900, 1280×720 and 390×844:

- `/app/today`: populated deterministic sample.
- `/app/today?scenario=empty`: configured empty sample.
- `/app/calendar`: empty/sample, with disconnected sources and manual entry.
- `/app/mail`: populated fictional messages, source evidence and review.
- `/app/notifications`: sample schedules and empty inbox.
- `/app/context`: empty public-forecast planner.
- `/`: desktop landing reference; no landing redesign was applied.

Local captures are generated in ignored `ui-review/before` and `ui-review/after`
directories. Each contains named PNGs plus `capture.json` with route, viewport,
capture timestamp and measured overflow/navigation height. Sample mail timestamps
vary with the local clock; this is a composition review, not a pixel-hash test.

To reproduce against a running local frontend:

```powershell
node scripts/capture-ui-review.mjs before http://127.0.0.1:3102
# After the UI change:
node scripts/capture-ui-review.mjs after http://127.0.0.1:3102
```

The capture helper waits for actual workspace readiness and fonts. Functional
browser checks additionally save review, validation-error, source and mobile-menu
screenshots in the ordinary Playwright results directory.

## Prioritized findings and changes

| Priority | Visible cause | Implemented change |
| --- | --- | --- |
| P1 | Nine mobile destinations occupied two rows and obscured more content. Account controls were less accessible on narrow screens. | Four frequent destinations plus More; all remaining daily/system routes and account controls remain available in a native modal dialog. Dock height measured 104→64px, recovering 40px. Quick Capture remains above it. |
| P1 | Calendar, Mail, Notifications and Commute had different heading scales, margins, notices and action treatments. | Shared `WorkspaceHeader`/`WorkspaceNotice`, consistent reading surfaces, quieter metadata and a clear light primary action. |
| P1 | Calendar manual entry lived far below the initial empty agenda. | Add event in the header, an explicit empty-state action and an on-demand editor with focus transfer and unsaved-close protection. |
| P1 | Notification hero consumed excessive vertical space while schedule and browser setup appeared as a long stack on wide screens. | Shorter heading, schedule-first two-column composition on desktop, single column on narrow screens, secondary rules behind disclosure. |
| P1 | Mail review had a large heading-to-content gap, equivalent visual weight across controls, and a distant save action. | Tighter split-pane hierarchy, clearer selected message/evidence, quiet refresh action and a visible review-save bar. Source and correction behavior are retained. |
| P1 | Generic sample shell state said “3 live signals”; search advertised only a Mac shortcut on Windows. | Sample scenario language in the shell, and Ctrl/Command keyboard hints. Workspace-specific mode/freshness labels stay explicit. |
| P2 | New route navigation could retain the previous scrolled position. | Routed content resets to the top and receives keyboard focus. |
| P2 | Provider setup copy described worker internals in daily-use views. | User-facing freshness/update language; deployment mechanics remain in setup documentation. |

## Verification and limits

The UI browser test checks workspace heading placement at laptop/desktop/mobile
widths, document and internal-content overflow, Calendar validation and safe
editor closing, mobile destination coverage, keyboard wrapping, Escape/return
focus and scenario-preserving navigation. Existing tests still exercise actual
commute API results, sample Calendar editing, Mail corrections and Notifications.
The ordinary frontend tests verify the locked cube byte hashes.

Final build and CI results are recorded in the PR. No real provider consent,
private hosting access, live-account sign-out or deployed acceptance was verified
by these mock-mode UI checks. Native dialog sign-out is wired to the existing
auth service with visible failure handling. Existing GPU/WebGL behavior is not
a claim of acceptable performance on every low-end device. Other daily screens
retain their typed mock behavior; this pass does not make them live.

Next roadmap integration remains Phase 11 — Notion and Microsoft Teams.
